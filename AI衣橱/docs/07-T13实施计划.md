## 全局约束与接口

- 所有业务 API 必须提供有效 UUID 的 X-Device-ID；缺失/非法/legacy 拒绝，绝不回退到全部数据。owner_id 为 derived，模型输出和 cases 不承担归属字段。
- 四业务表 owner_id 非空。历史所有行明确归 legacy，任何普通设备读不到；不改其原ID、属性、图片内容。
- 新设备照片与上传幂等均按 owner 隔离；相同 draft 在两设备不冲突。候选过滤只读本设备。
- 配额按 Asia/Shanghai 日界重置，识别20/编排30；模型请求启动前以SQLite事务预占，内部重试不重复扣，成功草稿缓存重传/候选不足不扣，启动后失败仍扣。
- daily_quotas 只存 sha256(device_id + 服务端盐)，不存原UUID；盐仅后端本地私密文件、重启保留。到次日0点失效并清理，启动及运行中清理过期记录。
- DELETE删除owner四表业务行、其照片与目录；保留当日匿名配额。与同owner写操作互斥，防止清空期间旧识别回写。
- 现有24件归 legacy。仅开发脚本 claim_legacy --device-id UUID，默认dry-run，--apply才认领四表；不提供线上认领API。
- Web只在 deviceId.ts 读写localStorage，所有请求及照片读取带同一设备UUID；Capacitor/Keychain不在本轮。
- D10-b必须先单独提交：上传一律待确认，PATCH五字段任一或“这是对的”解除；confidence仅辅助，不可冒充用户改写。
- prompt/cases断言/134冻结文件完全不改；新报告单独保存，旧九张报告不覆盖。
- 业务规则变更会更新对应测试的协议前置条件/期望，不删除、skip、xfail或放宽已有功能断言。
