## 1. 原文产品定位（第 1 页）

> 基于 AI 算法与大数据技术的智能穿搭解决方案平台，通过精准匹配用户身材、风格偏好、场景需求及实时环境因素，提供个性化穿搭建议与虚拟试穿服务。

**问题**：一句话里塞了 4 个匹配维度 + 2 个服务形态，没有边界。

---

## 2. 原文目标用户（第 1–2 页，6 类）

| 编号 | 人群 | 核心需求 |
|---|---|---|
| 2.1 | 穿搭选择困难群体 | 缺灵感，选衣耗时久 |
| 2.2 | 追求个性化与效率 | 按身材/风格/场景生成专属搭配 |
| 2.3 | 身材特殊或购衣困难 | 版型、尺码适配 |
| 2.4 | 服装管理实用主义者 | 用现有库存生成搭配，避免重复购买 |
| 2.5 | 电商购物高频用户 | 降低退货率 |
| 2.6 | 时尚爱好者 / 内容创作者 | 获取灵感与素材 |

**裁剪决策**：MVP 只服务 **2.1 + 2.4 的交集** —— 「衣柜里有货但不会搭、每天要花时间决策」的通勤上班族。
理由：2.3 需要 3D 建模，2.5 需要电商数据，2.6 是内容社区，三者都无法在单机 MVP 内闭环验证。

---

## 3. 原文核心价值（第 3 页）

1. 节省时间与精力 2. 提升穿搭自信 3. 降低购物成本 4. 拓展时尚视野

**MVP 只承诺第 1 条，且必须可量化**：把「早上决策 12–18 分钟」压到「30 秒内看完 3 套并选定」。

## 4. 原文功能清单（第 6–10 页）与裁剪结论

### 4.1 用户数据库（第 6–7 页）

| 原文功能 | 实现细节 | MVP 决策 |
|---|---|---|
| 身材数据：手动输入 / 手机 3D 扫描 / 穿戴设备同步 | 身高、体重、三围、体型 | **只保留手动输入身高体重 + 体型单选**；3D 扫描砍掉 |
| 服装数据：拍照自动解析款式/颜色/图案/材质，支持批量导入，识别不了的给手动补充 | PaddleClas 图像识别 | **核心保留**，这是 P1 约束（建档 ≤3 分钟）的落点 |
| 风格偏好：基础风格 + 关键词 + 1–10 级滑动条 | — | **简化为 1 个风格标签 + 1 个关键词**（原文第 21 页优化版也这样建议） |
| 场景需求：场合、时间、心情 | — | **保留场合 + 温度**，心情砍掉（无法验证） |

### 4.2 穿搭数据库（第 7–8 页）

| 原文功能 | MVP 决策 |
|---|---|
| 天气数据联动（气温/湿度/风速/紫外线） | **只取气温 + 降水**；MVP 允许手动选温度带，天气 API 为 P1 增强 |
| 节日热点、时装周主题 | 砍 |
| 身材适配策略库（苹果型/沙漏型/H 型 × 显瘦显高技巧） | **转为规则引擎里的硬约束**（不是内容库） |
| 流行趋势分析 | 砍 |
| 穿搭案例库 / 灵感广场 | 砍 |
| 服装材质库、版型 3D 展示 | 材质保留为单品属性字段，3D 展示砍 |

### 4.3 商品鉴别数据库（第 8 页）

官方标准库、市场样本库、风险特征库、PS 痕迹识别。

**整体砍掉。** 理由：需要海量真实订单与评价数据才能建模，"退货率 22%""商家信用分 4.2"这类数字在无数据源时只能编造，写进简历会被追问到底。原文第 4 页给出的「推荐适配率不足 40%」「退货率高达 28%」同样属于无出处的行业口径，不作为本项目的指标来源。

### 4.4 日常穿搭推荐场景（第 8–9 页）—— **MVP 主线**

原文流程：

1. 用户点「今日穿搭」，系统**优先从用户已有服装库中搭配**，生成 **3–5 套**方案，并展示**搭配理由**（例："基于今日降温，选择保暖毛衣搭配阔腿裤，显瘦又舒适"）
2. 不满意可语音/文字调整（"想要更正式的""换一件蓝色上衣"），支持单品「保留 / 替换」
3. 点方案进 3D 虚拟试穿，360° 查看，支持街景模拟
4. 自动存「我的衣橱日记」，可分享

**MVP 采纳**：第 1 步完整采纳（3 套 + 理由）。第 2 步降级为「换一套 / 排除某件单品」两个按钮（不做自然语言调整）。第 3 步**砍掉 3D**，改为「单品缩略图拼贴 + 组合文字」。第 4 步砍掉分享，只保留本地历史列表。

### 4.5 购物决策场景（第 9–10 页 + 第 27–28 页原型）

原文链路：商品录入（粘贴链接/拍照）→ 虚拟试穿 → 适配度报告（尺码/风格/材质/价格四维打分）→ 风险预警（退货率、商家信用分）→ 替代推荐 → 收货后反馈回写风险库。

**部分采纳，且改造成本项目最有价值的一环**：

- ❌ 砍掉：链接抓取、商家信用分、退货率、替代商品推荐、分佣（全部依赖电商数据，不可得）
- ✅ 保留并放大：原文第 32 页设计说明里那句「**网购识别结果自动同步至个人衣橱，成为穿搭推荐的潜在单品**」

改造后叫 **「买前试配」**：导入一件**还没买**的候选单品 → 计算它与现有衣柜的**可搭配覆盖率**（能配出几套合规搭配）→ 输出「值得买 / 不值得买」+ 能配出的搭配 + 缺什么。

这一步把「推荐买什么」翻转成「先算你衣柜吃不吃得下它」，是相对 Acloset / Cladwell / 搭搭的差异化点，且**完全在本地数据内闭环，无需任何外部数据源**。

### 4.6 技术方案（第 10–11 页、第 23–24 页）

原文：百度飞桨 PaddleClas / PaddleOCR / PaddleDetection、文心大模型多模态、DeepSpeech 语音、AR + Unity 渲染、点云重建。

**决策**：MVP 只用**一个多模态模型做单品结构化**（走统一 LLM 出口，不引入 Paddle 本地推理，避免环境依赖），编排用同一模型。语音、AR、Unity、点云全部不做。

> 如果坚持用文心（项目是文心大赛作品，简历上叙事更连贯），只需替换 `app/llm/client.py` 的实现，其余代码不动 —— 这也是把 LLM 收敛到单一出口的原因之一。

### 4.7 新原型页面（第 25–32 页）

原文 5 个页面：首页、网购识别流程页、日常穿搭推荐页、个人衣橱页、穿搭记录页。
视觉规范：浅蓝（科技感）+ 米色（时尚感）；风险橙/红，适配绿；手机小程序风格。

**MVP 保留 5 个页面的骨架**（首页 / 衣橱 / 建档 / 方案 / 记录），**网购识别页替换为「买前试配」页**。视觉沿用浅蓝 + 米色。

## 5. 原文中不可信 / 不采用的数据

写简历和答辩时**不要引用**以下原文数字，它们没有标注口径与来源，一问就穿：

- 「推荐适配率不足 40%」「退货率高达 28%」「贴合度误差 <2mm」「推荐准确率 85%」「拦截超 90% 虚假宣传」
- 「6 个月拉新 300 万」「月留存 40%」「每月 30% 首页流量」

替代做法：所有指标改为**本项目自己跑出来的**数字（20 条 case 的通过率、P95 耗时、衣柜外单品出现率），见 `docs/04-验收标准与失败处理.md`。

## 6. 一句话总结这次改造

> 从「一个想同时做 3D 试穿、商品鉴别、电商分佣、社交社区的平台」，
> 收敛为「一个每天早上 30 秒告诉你穿什么的机器，外加一个买前算一算的小工具」。
> 前者无法验收，后者每一步都能拿 case 证明。
