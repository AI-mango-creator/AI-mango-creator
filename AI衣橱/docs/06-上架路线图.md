# 06 · 上架路线图（App Store）

> 目标：把一个可在 App Store 点开的「算法衣橱」交到人手里。
> 决策前提（2026-11-13 确认）：**先用最小可过审范围拿上架结果** · **先 Capacitor 出包、再决定是否转 Expo** · **先海外区、后中国区**。

---

## 一、范围：能过审的最小集

上架版本只做四件事，其余全部砍掉：

| 功能 | 说明 | 现状 |
|---|---|---|
| 拍照/相册建档 | 上传 → 识别 → 校正 → 入库 → 卡片出现 | T5 上传链路开发中 |
| 衣柜查看与编辑 | 五字段 PATCH（D8 白名单） | ✅ 已完成 |
| 出方案 | 3 套搭配 + 理由 + 缺件提示 + 降级提示 | ✅ 已完成 |
| 数据管理 | 一键清空我的数据（本地 + 服务端） | 待做（成本低，建议做） |

**明确不做**：换一套交互（T9）、社交/分享、订阅付费、虚拟试穿、推送。
砍掉的理由不是做不了，而是每一项都会延长审核往返；上架之后再迭代不影响版本号。

### 关键设计决策：P0 不做注册登录

用**匿名设备 ID**（首次启动生成 UUID，存 Keychain）代替账号体系：

- 后端 `wardrobe_items` 增加 `owner_id`，所有查询强制带该字段，实现数据隔离
- 好处：省掉注册、登录、找回密码、账号删除四件事。Apple 5.1.1(v) 的账号删除要求只针对「提供账号创建的 App」，不做账号即不触发
- 代价：换手机/重装数据丢失。写进隐私政策与空状态文案即可，P0 可接受
- 仍建议提供「清空我的数据」按钮：一条 DELETE 接口，成本半天，能显著降低审核质疑

## 二、四阶段

### 阶段 0 · 今天就能开始（不依赖代码）

| 事项 | 说明 | 耗时 |
|---|---|---|
| 注册 Apple Developer Program | **个人账号 $99/年（约 ¥720）**，身份证实名，不需 D-U-N-S。个人账号审核 24–48h | 前置最长，今天就办 |
| 买域名 | 任意注册商，`.app` / `.com` 均可 | 10 分钟 |
| 准备隐私政策页 | 静态页托管在 GitHub Pages，免费；内容见 §四 | 2 小时（可代写） |

> 公司账号需 D-U-N-S 编号，1–2 周，P0 不需要。

### 阶段 1 · 一周：后端上线 + Capacitor 出包 + TestFlight

1. **后端部署**（海外区先跑）
   - Fly.io / Railway 单实例，SQLite 挂 persistent volume；并发低时够用
   - 必须 HTTPS（平台自带）、必须读环境变量、key 不进代码
   - 每设备日配额（如识别 20 张/天、编排 30 次/天）+ 简单限流，防额度被刷
2. **匿名设备 ID + 数据隔离**（约 1–2 天）
3. **Capacitor 打包**
   - `cap add ios`，装 Camera 插件，`Info.plist` 写相机/相册用途
   - 原生导航栏 + 安全区适配，避免"网页壳"观感
4. **TestFlight 内部测试**
   - 内部测试最多 100 人，**不需要 Beta 审核**，装好即可分发
   - 这一步就能拿到「iPhone 真机跑通 + 录屏 + 若干真实用户试用」的证据

**验收物**：TestFlight 邀请链接 + 一段 60 秒真机录屏 + 建档耗时实测（真机，不是脚本）。

### 阶段 2 · 两到三周：过审物料 + 提审

| 物料 | 要点 |
|---|---|
| 隐私政策 | 收集什么（照片、衣柜属性）、传给谁（百炼）、存多久、如何删除 |
| 隐私清单 `PrivacyInfo.xcprivacy` | 2024 起强制；相机/相册需声明用途 API |
| App 图标 / 启动图 | 1024×1024 无透明；启动图不能白屏 |
| 截图 | 6.7"、6.1"、5.5" 三套，每套 3–5 张，须用真机截图 |
| 举报入口 | AI 生成内容需可举报（Apple 1.2），一个"这套不合理"按钮 + 邮件即可 |
| 空状态 | 首次启动不能是空白页，要有"拍第一件衣服"引导 |

**提交后**：审核通常 1–3 天，被拒后 24h 内可重新提交。预留 2 轮往返。

### 阶段 3 · 中国区（与阶段 2 并行启动）

| 事项 | 说明 |
|---|---|
| App 备案 | 工信部要求，通过云厂商（阿里云/腾讯云）提交，需 App 名称、包名、隐私政策 |
| ICP 备案 | 域名 + 境内服务器，5–20 个工作日 |
| 服务器迁移 | 境内节点；数据不出境（百炼在境内，OK） |
| 内容安全 | 识别结果与编排理由需过内容审核；可接云厂商内容安全 API |

**顺序**：先海外区上架跑通审核流程，中国区备案同步走，不要串行等待。

## 四、常见拒因与预防

| 条款 | 拒因 | 预防 |
|---|---|---|
| 4.2 Minimum Functionality | 判定为「网页壳」 | 接相机、原生导航、本地缓存；首次启动有真实内容，不是 WebView 加载页 |
| 5.1.1 隐私 | 未说明照片用途、无隐私政策 | 用途文案写清"仅用于识别衣物属性，不上传人脸" |
| 5.1.1(v) | 有账号但不能删 | P0 不做账号即规避；仍提供「清空我的数据」 |
| 2.1 App Completeness | 崩溃、空数据、占位文案 | 用真机跑 20 次完整流程；后端挂掉要有中文提示 |
| 1.2 用户生成内容 | AI 输出无举报机制 | 加举报按钮 + 人工处理承诺 |
| 3.1.1 支付 | 站外支付 | P0 不收费即不触发 |

## 五、与现有任务板的关系

现有 T1–T12 是**验证线**（证明这套架构成立），上架是**交付线**（把它变成产品）。两条线的交点只有一处：

- **T5 上传链路**（进行中）既是验证线缺口，也是上架前置。它完成后，上架工作只剩工程包装与合规。

新增任务（待落任务板，编号从 T13 起）：

| 编号 | 任务 | 阻塞关系 |
|---|---|---|
| T13 | 匿名设备 ID + 数据隔离 + 配额 | 依赖 T5 |
| T14 | 后端公网部署 + HTTPS + 环境变量 | 依赖 T13 |
| T15 | Capacitor 打包 + 相机 + 真机验收 | 依赖 T14 |
| T16 | TestFlight 内部测试（≥5 人试用） | 依赖 T15 |
| T17 | 过审物料（隐私政策/图标/截图/举报/空状态） | 可与 T15 并行 |
| T18 | 提交审核 + 往返修复 | 依赖 T16、T17 |
| T19 | 中国区 App 备案 + ICP + 迁移 | 与 T18 并行 |

## 六、验收标准（上架版本的 DoD）

1. App Store 上有可公开访问的链接，能在真机下载安装
2. 从零开始：拍照 → 建档 → 出 3 套方案，全程 ≤ 90 秒，不崩溃
3. 断网 / 超时 / 识别失败三种异常均有中文提示且可重试
4. 隐私政策可访问，「清空我的数据」可用且后端同步删除
5. 至少 5 名非开发者通过 TestFlight 完成过一次完整流程，记录失败点

> 简历与比赛引用时写：「已上架 App Store（链接），TestFlight 内测 n 人，建档 X 秒（真机实测）」。这些数字全部可验证，比任何通过率都硬。
