# T19 · 首页与天气、档案、衣橱视觉改版设计

日期：2026-11-18。状态：设计与A→B→C范围已获人类批准，实施及真实天气验收完成。

## 意图与已确认范围

用户给出四张参考截图，希望还原排版，并已明确批准接入真实城市天气、增加后端接口、更新D2。对应图1首页、图2天气、图3档案、图4衣橱；首页“AI帮我搭”先进入图4式衣橱，衣橱中的AI搭配进入已有真实生成页。

既有功能为照片上传/识别/确认、十分类、编辑/删除、身材资料、过滤/编排/校验/降级。保留这些能力和设备隔离，不更换技术栈、模型、prompt、cases或冻结证据，不新增依赖。

## 方案与选择

采用现有React页面+FastAPI天气代理：复用现有API层和设备头，天气协议仍在models定义。相比重新搭建独立前端，这能保留已验证的上传与搭配行为；相比浏览器直接访问天气服务，代理可统一校验、超时和中文错误。依据现有架构，这是本轮的实现方案；不引入新的UI/路由/天气SDK。

天气提供方拟采用Open-Meteo非商业免费接口。官方文档已核实城市搜索与七天预报，页面标来源并链接。首次城市搜索实测200（深圳有多个同名结果，必须由用户选择，不能自动选第一条）；预报域名本机TLS连接失败，真实天气连通尚未验收，不以注入响应冒充。实现后的正式验收仍必须真实请求成功，否则天气部分保持未完成。

## 页面与视觉

共同采用上浅粉到白渐变、白色大圆角卡片、细线SVG图标、粉紫青渐变主按钮，最大480居中，375×812无页面横向溢出。日期/分类条可在自身容器内横向滚动。底部导航固定但给正文留足底部空间；不复制手机系统状态栏、灵动岛、第三方品牌或人物头像。

1. 首页：左侧“我的档案”头像占位入口、中部真实衣物数量、右侧城市及真实最低/最高温。五个快捷入口按相同卡片排版，使用已实现能力：我的衣橱、身材档案、天气穿搭、上传衣物、AI搭配。AI帮我搭大横幅采用原生CSS/SVG和个人衣物视觉，不引入第三方商品素材。下方双列图片区展示当前设备的真实衣物，不伪造商城/社区内容。空衣柜明确引导上传；读取失败可重试；天气和衣柜分别加载，天气失败不阻塞其他功能。
2. 天气：返回/标题、今天起七天胶囊日期条、当日天气卡（最低/最高温、天气中文名、城市、来源、获取时间）、规则生成的保暖提示、用此温度搭配按钮。城市搜索表单及多个同名候选。首屏未选城市显示选择引导，不默认深圳；不申请GPS权限。搜索无结果显示明确空态。切换日期显示真实对应预报；不展示虚构历史天气或历史OOTD。
3. 档案：顶部返回和“我的档案”，分区卡片展示现有身高/体重/体型摘要，编辑进入现有输入及五型示意；保存失败保留输入，设备切换保护仍生效。不增加人脸头像上传、多形象、肤色、修饰部位、手部档案等未批准数据模型。
4. 衣橱：图4式标题/真实总数、分类横栏及计数、三列白色图片网格；分类保留全部/上装/下装/裙装/套装/鞋子/包包/首饰/配饰/未分类。卡片保持待确认状态/编辑/删除能力，图片失败文字降级。底部“导入衣橱”触发原上传入口，“AI搭配”进入原生成页；不增加不可用的DIY/统计/历史/搜索按钮。
5. 搭配页：统一粉色卡片风格，保留温度/场合、真实生成、缺件、中文错误和可关闭降级黄条。天气跳转时预填当前所选预报日期最低温的四舍五入整数，显示来源日期/城市，可手改；跨日或刷新不把旧预报伪装成当前天气。

底部四入口：**首页 / 衣橱 / 搭配 / 我的**；替换截图里未实现的圈子，全部可用。上传快捷入口把用户带到原选图控件。导航切页取消未完成请求，避免旧城市响应覆盖新城市。

## 天气协议与错误

- GET `/api/weather/cities?q=<2..50字符>`：返回cities数组；每项id/name/admin1/country/latitude/longitude/timezone，最多5项。空结果200空数组。
- GET `/api/weather?latitude=<有限-90..90>&longitude=<有限-180..180>`：返回provider、timezone、fetched_at、days（7天），每项date/temp_min_c/temp_max_c/weather_code/中文weather_text。客户端显示城市名来自已选城市结果；后端不接收任意URL，不转发设备头或其他个人资料到供应商。
- 天气仅供决策参考，不将第三方预报称为实测气温；不调用LLM生成天气文案，不改变S2规则阈值。天气建议复用filter的temperature_band，按最低温给固定保暖提示，不捏造衣柜里存在的单品。
- 单次天气/城市上游请求总超时8s、无自动重试，无缓存/队列/新数据库表。沿用X-Device-ID校验。参数错400，上游超时504，上游不可用/格式错误502，均中文提示。用户可点重试，仍可手填温度生成。
- 前端API独立weatherApi.ts：设备头、AbortSignal+超时组合、Pydantic对应字段检查、中文错误。城市/选择日期/天气只放App页面状态，本轮不持久化位置；刷新重新选城市，页面明确显示未选择状态。无需修改设备UUID存储模块。
