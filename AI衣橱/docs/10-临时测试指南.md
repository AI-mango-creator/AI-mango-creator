# T16 · 临时HTTPS测试版

目标：朋友点开链接，即可在手机浏览器上传上衣、裤子、鞋的照片，逐件确认后生成搭配。无需云账号、域名或Docker；使用现有真实模型API，调用会消耗账号额度。

## 启动与使用

在仓库根目录、人类终端中运行：

```bash
make share
```

脚本构建生产网页，启动127.0.0.1:18080的FastAPI与临时HTTPS通道；**只有公网/health实测200后才打印“测试链接已连通”**。把终端打印的HTTPS地址发给朋友，不能发送127.0.0.1或localhost地址。

1. 新浏览器进入“我的衣柜”，初始为空；选择或拖入真实照片，逐张上传。
2. 每张上传后点“这是对的”；识别有误时点卡片修改品类/子类/颜色/材质/图案，再保存。
3. 切“今天怎么穿”，填写当天温度与场合，点击生成。只用已有衣物，候选不足显示缺件；冷天还需要外套，不能靠三件薄衣硬凑。
4. 可以编辑或删除单品；图片暂时读不到时用文字占位。

推荐脱离当前终端后台运行（不要和正在运行的make share同时启动）：

```bash
.venv/bin/python -m scripts.share --background
# 查询并验证最新地址
.venv/bin/python -m scripts.share --status
# 停止后台分享及其子进程
.venv/bin/python -m scripts.share --stop
```

后台启动返回后主进程继续运行，日志在`data/share/launcher.log`。`make share`仍为前台运行，Ctrl-C停止；后台模式用`--stop`停止。

需要保持电脑开机联网和分享进程运行。Mac脚本运行期间会用系统自带caffeinate抑制空闲睡眠，合盖、断网、关机仍可能断开。Ctrl-C停止分享；重新启动可能换新链接。当前地址仅在运行期间保存在忽略提交的`data/share/share.json`。

分享期间每15秒访问公网`/health`保活，不调用模型。短暂502不会立即关闭本地服务，会等待网络恢复；免费域名轮换时从通道日志读取最新地址，先验证公网health再原子更新share.json；旧地址不会自动跳转。SSH或服务实际退出仍需重新运行，持续断网不能保证恢复。保活不等于长期可用保证。

## 数据、额度与通道

- 分享版数据库：`data/share/app.db`；照片：`data/share/uploads/`；模型日志、匿名配额盐和锁同目录。不会导入本机`data/app.db`或旧衣柜。停止分享不会清空照片，便于同一链接/浏览器继续；链接域名改变后浏览器设备ID通常会重建，原数据不会自动认领。
- 每个浏览器设备的衣柜隔离，沿用UUID、来源审计与用户确认；设备ID不是账号，不提供跨设备同步。
- 全站按北京时间每日最多识别20张、生成30次，同时保留既有每设备20/30限制。进入模型调用的业务请求即使失败也占一次额度；参数/图片格式校验失败、成功草稿缓存重传和不调用模型的缺件结果不额外消耗模型业务额度。一笔业务请求的模型重试仍遵守D7.1。计数与业务数据清空分离，更换设备ID不能绕过全站上限；这不是以人民币计的费用上限。
- 如需调整总额度，在明确可承担调用成本后运行：`.venv/bin/python -m scripts.share --recognition-limit 20 --composition-limit 30`。普通`make dev`不启用全站限制，默认本地数据路径不变。
- 优先使用上次成功的通道；初次尝试Cloudflare。自动下载的官方cloudflared固定2026.11.0，安装前核对官方release的SHA256，只放在`data/tools/`，不安装全局软件或改npm/pip依赖。
- 当前网络若阻断Cloudflare的7844端口，自动尝试localhost.run备用HTTPS通道，使用macOS自带SSH；不读取用户SSH配置、私钥或agent，主机首次信任记录仅放`data/tools/share_known_hosts`。可用`--tunnel cloudflare`或`--tunnel localhost`指定。
- 通道商负责转发HTTPS请求，照片持久化仍只在这台电脑。API密钥只留后端；脚本在公开前检查构建产物不含当前密钥。目录、.env、数据库和照片目录不作为静态文件公开，照片仍通过带设备头的API读取。

通道是短时试用服务，不承诺固定地址、速度或可用性。仅把链接发给参与测试的人；不要把他人的私人照片用于公开演示。无需打开路由器入站端口。

依据：[Cloudflare临时通道](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)、[Cloudflare防火墙端口要求](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/configure-tunnels/tunnel-with-firewall/)、[localhost.run免费通道](https://localhost.run/docs/forever-free)。

## 故障与验收

- 看不到“已连通”：检查`data/share/server.log`、`cloudflare.log`或`localhost.log`；没有真正连通的地址不算交付。
- 额度用完：中文429提示，次日0点重置；清空衣柜不会恢复额度。
- 上传失败：图片与草稿保留，原地重试；不要因等待而重复创建不同草稿。
- 免费通道带宽较低，优先用裁去无关背景、较小的JPG测试；公网方案照片曾实际超过既有10s读取期限，页面会显示品类·子类文字块，搭配理由仍可用，不保证每张缩略图都能正常显示。
- 候选不足：先确认刚上传的衣物，再按提示补缺件或选择适合其厚薄/季节的温度；不预置衣柜冒充上传。
- 出现`no tunnel`：旧免费域名可能失效，先运行`.venv/bin/python -m scripts.share --status`查询已验证的最新地址，再重新发给测试者。若查询失败，检查`launcher.log`及通道日志，确认电脑联网和进程存活；分享结束才重新启动。不要重复启动多个分享进程。
