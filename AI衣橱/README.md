# 算法衣橱 · Wardrobe Copilot

面向出门前需要从已有衣柜中快速选衣的通勤人群，输入衣柜照片、温度和场合，输出可执行搭配、属性理由与缺件提示。当前是P0验证原型，开发时间2026.11至今，未整体结项：照片上传→识别入库→用户确认→真实编排已接通，支持单品删除和方案图片预览；换一套交互待完成。

项目范围、完成度和实测证据见[任务板](docs/tasks.md)，功能与限制见下文。现可用`make share`生成临时HTTPS测试链接，见[临时测试指南](docs/10-临时测试指南.md)；长期线上地址和完整演示视频仍未提供，下面的localhost地址只用于本地运行。

## 我的中心与每日穿搭

底栏“我的”提供生成历史、收藏、发布、私密OOTD和衣柜搭配。每日首次访问按北京时间记10积分，不能充值或抵扣AI调用；OOTD可保存穿搭照片或自有方案，默认仅自己可见。顶部可打开档案、积分明细、收到的互动及设置；设置支持头像昵称、反馈和清空本设备数据。清空同时删除积分流水，今天已领取的积分不补发。

本轮409项后端测试、76项前端测试、lint/build通过；[T22实测与26张移动端截图](docs/reports/t22-personal-center.md)记录隔离测试素材、失败注入和功能边界。仍使用设备身份，没有手机号绑定或多设备找回；截图中的试穿历史是明确标注的离线验收记录，真实试穿验收继续按T21安排。

## 发链接给朋友测试

在本机终端执行`make share`，等待输出“测试链接已连通”，复制HTTPS链接给朋友；上传衣物后先逐件确认，再输入温度/场合生成搭配。电脑与分享进程须保持运行，前台Ctrl-C停止。需要退出终端后继续分享时，改用`.venv/bin/python -m scripts.share --background`启动，`--status`查询验证最新地址，`--stop`停止；免费地址轮换后需重新发链接，旧链接不会跳转。使用独立测试库，全站每天最多识别20张/生成30次，不导入原衣柜；API调用仍使用真实模型并消耗额度。免费通道较慢，照片超时会退为文字占位。实际三张上传、确认、一次真实生成及双设备隔离记录见[T16报告](docs/reports/t16-share.md)。

## 30 秒跑起来

前提：已安装Python 3.11、Node 22 LTS，仓库依赖已就绪，`.env`已填写有效API配置。在仓库根目录执行：

```bash
make seed
make dev
```

打开 [http://127.0.0.1:5173](http://127.0.0.1:5173)。`make dev`同时启动后端8000、前端5173，Ctrl-C一起退出；前端通过Vite代理访问`/api`。`make seed`幂等灌入legacy隔离区，普通设备不可见；新设备衣柜为空，不会自动收到测试衣物。需演示基准衣柜时，仅在本地显式用下文`seed --owner-id`。

打开后先进入粉色首页，可查看个人衣橱、档案、天气和AI搭配入口。“衣橱”页可选择/拖入衣物照片自动建档，失败保留照片并原地重试；可编辑品类、子类、颜色、材质、图案；在衣橱顶部切到“AI搭配”，以18℃、通勤生成方案。上传后每件先待确认，点“这是对的”或编辑五字段保存后再参与搭配；confidence仅辅助。新设备先建档确认再生成；请求统一携带设备UUID，编排实际调用模型。授权、限流、超时或解析错误进入规则降级时显示基础搭配黄条；其他失败显示中文错误提示；候选不足显示缺件卡。

卡片右上角可删除单品，二次确认后硬删除历史引用并清理空方案；共用照片最后一件引用删除后才清理，失败保留卡片。方案按上装/下装/鞋展示缩略图，冷天外套继续显示；图片加载或解码失败转品类·子类文字块，原理由保留。[T15截图及验收边界](docs/reports/t15-experience.md)有完整说明。

### 首页与真实天气

首页采用浅粉渐变、个人衣物双列图墙与底部导航；衣橱为三列图片网格。天气页可搜索选择城市、查看真实七天预报，将所选日期最低温带入搭配并手动修改。数据来自Open-Meteo，仅当前会话保留城市、不申请GPS；超时可重试或手填温度。真实城市搜索/七天预报及27张375×812截图见[T19报告](docs/reports/t19-home-weather.md)。

### 服饰试穿体验（T21：离线部分完成）

首页“我的衣橱灵感”已替换为服饰体验目录，首页上传快捷入口移除，衣橱内仍可正常上传。目录明确标注“体验素材 · 暂无平台合作”，不编造品牌、价格、销量或购物车功能；未获得素材前显示空态。体验服饰不进入个人衣柜或推荐候选集。

点开服饰后可选择本人/获许可的人像照片，确认处理说明后开始试穿；支持异步任务、处理中、结果/原图切换、失败保留输入与本人删除。默认路径通过后端FASHN原生API，本轮按人类决定**没有发起真实生成**，尚不能宣称真人试穿效果或速度已验证。图片只按设备提供，不自动发布到社区；清空设备数据会删除试穿照片/结果及任务，匿名当日额度保留。

本机配置仅填后端`.env`的`FASHN_API_KEY`，不要发在聊天或写入前端。当前候选模型`tryon-v1.6`；启用前须确认账号、费用及照片使用许可。默认每设备每天3次试穿，分享模式全站10次；提交结果不明不自动重发。供应商可能临时处理图片并保留请求元数据，本地删除不代表远端任务取消或供应商记录删除。

目录由开发者在本地导入有使用权的素材，不会抓取淘宝/拼多多/闲鱼。准备本地JSON数组，例如下列模板（真实填写来源与使用权，不要照抄占位）：

```json
[{"id":"your-top","title":"实际素材名称","category":"tops","photo":"./your-photo.jpg","source_label":"实际来源","rights_note":"实际使用权说明"}]
```

支持`tops`、`bottoms`、`one-pieces`；图片JPG/PNG/WebP、不超过10MB。先检查，再明确应用：

```bash
.venv/bin/python -m scripts.import_tryon_catalog /absolute/path/manifest.json
.venv/bin/python -m scripts.import_tryon_catalog /absolute/path/manifest.json --apply
```

默认导入`data/app.db`；分享模式使用独立`data/share/app.db`，需显式加`--db data/share/app.db`。不把人物、结果、私有素材或真实key提交GitHub。离线接口与23张375×812截图见[T21报告](docs/reports/t21-tryon-experience.md)，其中供应商结果为明确标注的测试注入，不是真人试穿。

### 真实社区

底栏为“首页 / 衣橱 / 社区 / 我的”，AI搭配合并到衣橱顶部。社区包含关注、全部、搭配、投票四栏；右上角相机可发布穿搭照片、衣橱搭配、穿搭投票或“买不买”。帖子详情支持关注、点赞、评论和投票，每设备每帖一票、提交后不可更改；本人可删帖撤回。

其他测试者只会看到你主动发布的图片副本与文字，私人衣柜、设备UUID和身材资料不会随帖公开。删除私人单品不会撤回已发布副本；删帖或清空设备数据才会撤回。仍使用当前设备身份，清除浏览器存储可能失去管理旧帖的能力，没有新增注册登录。新社区初始为空，不预灌参考图中的作者、照片或互动数字。

[T20验收报告](docs/reports/t20-community.md)记录双设备真实发布/互动/清空、34张375×812截图，以及故障注入下的保留草稿与图片占位。社区无需调用模型。

### 身材资料与衣橱分类

“身材资料”页可填写身高（cm）、体重（kg），从X/A/T-Y/H/O五种带示意图的体型中选择；可留空或清除。资料按设备保存，只供搭配理由参考，不作为硬性筛选或合身保证。

衣橱支持全部、上装、下装、裙装、套装、鞋子、包包、首饰、配饰、未分类十个入口。外套归上装，半身裙与连衣裙归裙装；未分类须选择归属并填写具体品类名称，上装/裙装另明确搭配位置。套装、包包、首饰本轮仅收纳，不新增推荐槽位。资料与分类的[测试及手机截图](docs/reports/t18-profile-categories.md)已记录；新识别v3和带资料编排v2尚未做真实模型复测。

### 首次准备

首次准备需要uv；已有`.venv`和`web/node_modules`时保留现状。仅在缺失时准备，Python依赖使用锁定版本：

```bash
test -x .venv/bin/python || uv venv --python 3.11 --seed .venv
make setup
test -d web/node_modules || (cd web && npm ci)
cp -n .env.example .env
```

编辑`.env`，填写`DASHSCOPE_API_KEY`、账户对应的OpenAI兼容`DASHSCOPE_BASE_URL`及`DASHSCOPE_MODEL`。已验证文本模型为`qwen3.8-flash`；识别使用`qwen3.8-omni-flash`。密钥只由后端读取，不进入前端。

健康检查与单次真实生成：

```bash
curl -s http://127.0.0.1:8000/health
curl -s -X POST http://127.0.0.1:8000/api/outfits \
  -H 'X-Device-ID: <设备UUID>' \
  -H 'content-type: application/json' \
  -d '{"temp_c":18,"occasion":"commute"}'
```

将`<设备UUID>`替换为浏览器Network请求头中的X-Device-ID；设备ID只由deviceId.ts管理，组件不直接读localStorage。照片请求也带设备头，前端以blob显示。健康响应为`{"status":"ok"}`。生成响应含方案或结构化缺件、`latency_ms`、`degraded`、`degrade_reason`、`prompt_version`；真实模型调用会消耗API额度。
